# Visual parity

**You own pixel-exact equivalence. The baseline is the spec. You do not touch it.** Equivalence is verified by image diff, not by eye.

For matching two implementations of one screen (a UIKit screen rebuilt in SwiftUI, a custom control replaced by a system one) or migrating a styling system (design tokens, fonts, a spacing scale) without a visible change. A change that is meant to look different is `playbooks/ui-pass.md`.

1. **Establish the baseline before any migration.** A blocking prerequisite, not a follow-up. Pin everything that could move a pixel. This checkout's simulator (`scripts/ai/sim.sh udid`, its device type and OS runtime recorded), the status bar (`scripts/ai/sim.sh statusbar`), a seeded store through a seam, and every state the component shows. Capture each state at the kit's three sizes. Default (`scripts/ai/sim.sh size large`), dark (`scripts/ai/sim.sh appearance dark`), and the largest accessibility size (`scripts/ai/sim.sh size accessibility-extra-extra-extra-large`), each with `scripts/ai/sim.sh shot <png>`, or all of them with `scripts/ai/visual.sh <screens>`. Store it under `.build/parity/<slug>/baseline/` with the commit it came from and a `shasum` of every file. When matching two implementations, capture the target the same way. No baseline, no parity claim. **Check.** A second baseline run on the same commit diffs to zero pixels. If it does not, freeze what moves (a clock, a cursor blink, an animation, a random seed) through a seam until it does.
2. **Prove the diff can see.** `scripts/ai/sim.sh compare` lays images side by side for eyes. It does not count pixels. Write the diff as a lever (principle-build-the-lever), a small Swift script in `.build/parity/<slug>/` that reports the count of differing pixels and writes a mask of where they are. Bracket it (principle-explain-the-number). Baseline against itself reads zero, and a 1pt padding change reads nonzero. **Check.** Both bracket cases read correctly.
3. **State and hold the anti-shortcut clauses.** No harness changes, no baseline tampering, no tolerance added after the fact, and no restructuring of a component just to make a diff pass. If the baseline looks wrong, stop and ask. Do not edit it. **Check.** The baseline and harness `shasum`s match the ones recorded in step 1.
4. **Migrate shared primitives first, then one component at a time.** Tokens, fonts and shared modifiers are a blocking phase. After that, one owner per component, each in its own worktree (`scripts/ai/worktree.sh new parity-<component>`) so builds and simulators never collide (principle-separate-before-serializing-shared-state). A worktree gets its own simulator. Confirm it is the same device type and OS runtime as the baseline's before diffing, or the diff measures the simulator. Delegate each component to an `ios-agent` subagent (model from `MODEL_CODE` in `.claude/ios.env`, `sonnet` by default) with the component, its baseline paths and the diff command. **Check.** The shared primitives diff to zero on every screen that uses them before any component starts.
5. **Verify each component against its baseline** with the diff, at all three sizes and every state. A nonzero diff is a fail. Open the mask and the side-by-side (`scripts/ai/sim.sh compare out.png baseline=a.png now=b.png`) to see the delta, find its cause, and fix the migration, not the baseline. Run `/loop` per component until the diff is zero. **Check.** Zero differing pixels for every state at every size.
6. **Run `/verify`, then the Opening a PR playbook** (`playbooks/opening-a-pr.md`, `scripts/ai/pr.sh`) per component or per safe batch. `/verify` runs the gates and the AI judge on the visual sheets, recorded by `scripts/ai/history.py judge`. Put the diff table in the PR. **Check.** Every gate passes, and the PR link exists.

**Reply:** the components migrated; the diff result for each, per state and size; the baseline and harness location with their recorded hashes; what is left.
