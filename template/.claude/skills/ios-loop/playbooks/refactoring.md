# Refactoring

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to `playbooks/feature.md`. Large or cross-cutting structural work belongs to `/figure-it-out`. This playbook is the focused-to-medium change.

1. **Pin the behavior contract first.** Run `/how` over the affected subsystem to learn the contract. Then write the pin before any structure moves. A characterization test in Swift Testing or XCTest that calls the code the way its callers do and asserts today's literal outputs (principle-test-behavior-not-implementation). For a view, today's visual sheets (`scripts/ai/visual.sh <screens>`) and `expect:` labels in `.claude/ios-screens.txt`. For persisted data, a fixture store read back through the new code. If the area has no coverage, write the pin before touching structure. A clean build is not a pin. **Check.** The pin passes on the unchanged code and fails when you break the behavior on purpose.
2. **Name the structure the code is missing** (principle-model-the-domain). An enum with payloads over parallel optionals, a state machine over scattered booleans, a table over a `switch` repeated in three files, one type over a shape assumption copied across views. Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection. **Check.** You can name the branches or states the reshape removes.
3. **Name the target shape.** State the module layout, the types and the call graph as if built today (principle-foundational-thinking, principle-redesign-from-first-principles). Say which actor owns each piece of state. If the target crosses a function boundary, run `/architect` to explore the shape before the move. **Check.** The target is written in the todo list as Swift signatures.
4. **Subtract before you add.** Delete dead code, collapse one-caller wrappers, drop redundant validation inside trusted types, and remove orphan references before introducing the new shape (principle-subtract-before-you-add). The smallest change that reaches the target ships (principle-laziness-protocol). A speculative cleanup that "might help" gets reverted. **Check.** The subtraction is its own commit, and the pin is still green.
5. **Move in small behavior-preserving steps,** each keeping the pin green. For an API reshape, migrate every caller and delete the old API in the same wave (principle-migrate-callers-then-delete-legacy-apis). No compatibility shims, no parallel old and new paths. Delegate the mechanical edits to an `ios-agent` subagent (model from `MODEL_FAST` in `.claude/ios.env`, `haiku` by default; `MODEL_CODE` when the edit needs judgment) with a specific scope: the file paths, the names being moved, the behavior to hold. Move files on disk in a synchronized folder, or through `XcodeMV` with explicit groups. Never hand-edit `*.pbxproj`. **Check.** `scripts/ai/build.sh` and the pin pass after each step.
6. **Spot-check every rename against the files.** Renames silently miss usages the compiler cannot see. On iOS that means `#selector` and `@objc` names, Core Data entity and attribute names in the `.xcdatamodeld` and in `NSPredicate` format strings, `Codable` keys (renaming a stored property changes what is encoded, which breaks persisted data; principle-additive-data), String Catalog keys, storyboard and XIB references, launch arguments and their lines in `.claude/ios-screens.txt`, and prose in docs. **Check.** A `grep` for the old name returns only what you meant to keep.
7. **Prove behavior is unchanged on the real artifact,** not "it compiles" (principle-prove-it-works). Run the full suite with `scripts/ai/test.sh`. Run `python3 scripts/ai/blast-radius.py <changed files>` and re-capture every surface it names. Lay each before and after capture side by side with `scripts/ai/sim.sh compare out.png before=a.png after=b.png`. For a larger reshape, run an equivalence check, such as a script that diffs old and new outputs over recorded inputs. **Check.** Tests green, and every before and after pair shows no difference you did not intend.
8. **Confirm the change is worth keeping.** The success measure is reduced reader load (principle-minimize-reader-load). Count the layers, branches and mutable state a reader must hold, before and after. If the diff does not lower reader load somewhere, revert it. **Check.** The before and after counts are in the reply.
9. **Run `/verify`.** It runs the gates, then the AI judge on the visual sheets, recorded by `scripts/ai/history.py judge`. **Check.** Every gate passes and the visual verdict is PASS.
10. **Rebase into small ordered commits.** A subtraction commit, then the reshape, then any follow-on cleanup, each green on its own (principle-sequence-verifiable-units). Stage by path. Then run the Opening a PR playbook (`playbooks/opening-a-pr.md`, `scripts/ai/pr.sh`). **Check.** Each commit builds and passes the pin, and the PR link exists.

**Reply:** the structure that changed; the pin you held it against; the equivalence proof with its evidence paths; the reader-load delta; what shipped and what got reverted; the PR link. No new behavior.
