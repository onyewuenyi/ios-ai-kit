# Session pickup

**You own the resume point. Read the prior trail, don't redo it.** For picking up a paused session, another session's work, a cloud session's branch, or a run that died.

1. **Take bearings.** `git fetch && git status && git log --oneline -10`. The session-start bearings already name uncommitted work, an unverified HEAD and PRs that need the owner. `python3 scripts/ai/prs.py` lists every open unit. `python3 scripts/ai/history.py last` shows the last gate run on HEAD. Uncommitted files may belong to another session sharing this checkout. Leave them alone. **Check.** You can say which branch, worktree and PRs the prior work lives on.
2. **Locate the prior trail.** In this order. The resume note (`playbooks/pause-safely.md` writes it where the next session looks, usually the project's TODO or a note file it names). A decision trail (`decisions.tsv`, per `/show-me-your-work`). The prior transcript under `~/.claude/projects/<repo path with every non-alphanumeric as ->/*.jsonl`, or its worktree's directory. A cloud session link (in the PR body, or the cloud task list `/lead` keeps). A pushed branch. Read only this repo's and its worktrees' transcript directories. Never glob across `~/.claude/projects/*`, which reads private sessions from unrelated projects. Read the last messages first, then scan back for the decision points. Parse a long transcript in a subagent (`Explore`, or `/recall`) and keep only the reduced timeline here (principle-guard-the-context-window). **Check.** You hold a timeline of decisions with their evidence, not a transcript dump.
3. **Reconstruct operational state.** The branch and worktree, its simulator (`scripts/ai/sim.sh udid` run inside that worktree), the seams and launch arguments in use, what already landed (`git log`, `git diff` against the base), the open todos, the decisions made. The prior trail is authoritative input. Resist the urge to re-derive it. **Check.** Every item of the resume note or timeline maps to a commit, a file or an open todo.
4. **Diff done against pending.** Compare what shipped with what was planned and name the resume point. Do not re-run the prior reproduction or redo completed work. A "let me verify from scratch" pass treats an authoritative trail as untrustworthy. **Check.** The resume point is one sentence naming the next step.
5. **Verify the inherited claims on the real artifact, once.** A "done" in a trail is a claim, not evidence (principle-prove-it-works). Rebuild (`scripts/ai/build.sh`) and check the last claimed state the cheapest honest way. `python3 scripts/ai/history.py verified <sha>` exits 0 when that exact commit passed every gate on a clean tree. Otherwise drive the one seam or test the claim names. This checks the claim, it does not redo the work. If the claim fails, that failure is the resume point. **Check.** The last claimed state is confirmed with a gate result or evidence path, or named as broken.
6. **Route the rest.** Pick the verdict (continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or write the postmortem of a failed run) and hand the remaining work to the matching playbook. That playbook owns the rest. **Check.** The matching playbook's steps are in the todo list.

**Reply:** where the prior session stopped, what you inherited and what you redid (ideally nothing), the evidence for the inherited state, the resume point, and the playbook that now owns the work.
