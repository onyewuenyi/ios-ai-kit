# Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from idea to merge through `/ship`, and nothing merges without your clean verdict.** For "autopilot this queue", "full autopilot", and one-owner-per-PR programs. In `playbooks/orchestrate.md` the coordinator lands verified work and workers never merge. Here each PR's owner carries the whole lifecycle through the merge, and you, the root, keep only verification, countersigns and audits. The operator's full-autonomy grant plus your clean verdict is the merge authorization that babysitting alone never has.

1. **Mark the operator's items and honor state-then-wait.** Items the operator names stay with the operator. Their owners stop at merge-ready and the operator merges. When the operator asks for the protocol or the plan to be stated, state it and stop. Execution starts only on the operator's explicit go. **Check.** The queue is written down with each item marked owner-merges or operator-merges, and the go is on record.
2. **Spawn one owner per PR, running `/ship`.** Each owner is a fresh local subagent (Agent tool, `isolation: "worktree"`, `run_in_background: true`, `model` from `MODEL_CODE`, or `MODEL_JUDGMENT` for the hardest items). Its own worktree gives it its own simulator. Its brief follows the brief template in `playbooks/orchestrate.md`, and `/ship` gives it the lifecycle. Branch, implement through the matching playbook, `/verify` with the AI judge, open the PR ready with `scripts/ai/pr.sh`, triage review comments per `../references/review-triage.md`, run `/unslop` and `/no-comments` on the diff, babysit to green per `playbooks/babysit.md`. The owner's brief overrides one step of `/ship`. It never runs `scripts/ai/merge.sh` until the root's clean verdict for its head arrives.
   - Within about 15 minutes, the owner starts a `decisions.tsv` trail per `/show-me-your-work`, pushes its first branch snapshot, and opens the PR ready, never draft. After that it pushes after every verifiable unit. The trail stays uncommitted and comes back with its reports.
   - As soon as a subagent of its own starts, the owner adds its id, expected runtime (at least the longest past run of that kind) and state to a `children.tsv` kept the same way.
   - Before the code-ready report, the owner merges the default branch into its branch once, whether or not it drifted. In fix rounds it keeps that base. It merges the default branch again only at merge prep (step 5), on a conflict with trunk, or on a CI failure caused by a change on trunk. It never rebases and never force-pushes.
   - When the shipped code is final, the owner reports the code-ready head SHA, and the SHA of each later push that changes the patch. It reports merge-ready with the head SHA when `/verify`, CI and babysit are done.
   - A unit that needs no Xcode may go to a cloud owner (`scripts/ai/cloud.sh "<brief>"`). A cloud owner cannot verify or merge (`merge.sh` refuses in the cloud), so the root assigns a local owner to take its PR from code-ready through `/verify` and the merge.

   **Check.** Every owner has pushed a branch and opened a PR within its first 15 minutes, and its trail exists.
3. **Run owners in true parallel and never stack.** Self-contained PRs branch straight off the default branch, one writer per branch, disjoint files, drift absorbed by merging the default branch in. Only genuinely overlapping work serializes, merge then branch. Local owners are capped by the Mac at two or three simulator-heavy ones at once. **Check.** No two in-flight owners write the same file, from `gh pr view <n> --json files`.
4. **Swarm-verify every round before its merge.** A round starts at the owner's code-ready head SHA and at each later push that changes the patch. At that SHA, fan out independent lanes per `/swarm` and aggregate them into one verdict. Audit the receipts in the merge-ready report before you write the verdict.
   - **Gates lane.** `scripts/ai/verify.sh` at that SHA in a fresh worktree (`scripts/ai/worktree.sh pr <n>`), with the AI judge's visual verdict.
   - **Live lane.** Drive the load-bearing behavior on the simulator with the `ui-verify` agent, a seam (`scripts/ai/sim.sh launch <args>`) and `scripts/ai/xcui.py` assertions, at the default and the largest text size. The live lane is the floor. A verdict without it is not clean.
   - **Regression lane against trunk.** Run the same scenario on the default branch and on the head. If trunk lacks the feature, record that and gate the behavior the diff adds plus the end state the user waits for, instead of inventing a trunk result.
   - **Audit lanes.** Two or more `review-lens` agents over the diff, each with one lens (concurrency, persistence, lifecycle, ui-extremes, accessibility, privacy-review, performance), distrusting the PR body.

   Send every proven finding back to the owner in one fix-forward, including a defect a lane filed as a note. Each behavior finding asks for a failing test that covers every site with the same defect, or a repro receipt where no test can show it. Add that defect to the next round's audit brief. A new head gets a fresh swarm and a fresh verdict, except for lane results that stay valid under the patch-id rule in `playbooks/shipping.md`. **Check.** The verdict names the head SHA it covers, and every lane returned PASS at that SHA.
5. **On a clean verdict the owner merges, and a fresh owner takes the next item.** Merge prep never starts before a round's lanes start. It ends with the default branch merged into the head right before the merge, the new head SHA reported, `/verify` and CI passing on it, and the patch-id unchanged from the verdict's (or a fresh round). Then the owner runs `scripts/ai/merge.sh <n> --yes --wait <seconds>`, which merges only when `python3 scripts/ai/prs.py --check <n>` says merge-ready. A fresh owner, not the old one, takes the next self-contained item. Operator-named items stop at merge-ready for the operator. **Check.** `gh pr view <n> --json state` shows `MERGED`, and the next item has a new owner.
6. **Run the root layer.** A genuinely new raise of a pinned value (the warnings baseline `.claude/ios-warnings.txt`, an eval floor, a performance budget) needs your fresh countersign, granted only after verifier proof. Absorbing a value that already landed on the default branch is drift, not a raise. You never bypass an approval GitHub enforces. Run an audit tick every hour. On the operator's go, arm `/loop 1h` with a prompt that runs the tick. Never leave the cadence to memory or to completion notifications.
   - At each tick, re-read this playbook from trunk (`git show origin/main:.claude/skills/ios-loop/playbooks/autopilot-full.md`) and audit the operation against it. Fix drift in that tick.
   - Probe each owner read-only and collect the trails. Count only side effects as progress. Commits, pushes, PR or check changes, store reports.
   - A lane or owner that errors, or that passes its expected runtime with no side effect, is stuck. Stop it (TaskStop), record it as stuck, and dispatch a fresh replacement with consolidated scope at once. Apply the same test to every owner's `children.tsv`. A stall never proves or drops the work.
   - When merges batch, run a retro pass and a post-merge sweep of review comments.
   - End the tick only when no delegated work is left, even after the last merge.

   **Check.** The tick's row in your trail names what changed, or says none.
7. **Stand down instantly on the operator's stop.** A hold reaches every owner as a zero-writes order at once. Owners keep their briefs until the operator releases them. **Check.** No push lands after the stop, from `git ls-remote`.

**Reply:** the queue with each PR's owner, state and head SHA, each verdict and the lanes that produced it, what merged and what each fresh owner took next, countersigns granted and why, open operator gates, and where the collected trails live.
