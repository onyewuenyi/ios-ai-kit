# Bug fix

**You own this task. Plan, review, verify.** Delegate the hunt's wide reads and the fix to subagents. Stay in the lead.

Be scientific. Every shipped line traces to runtime evidence. A change that "might help" is a hypothesis, and hypotheses do not ship. When evidence refutes one, revert what it motivated. The smallest change the evidence justifies ships, nothing more (principle-fix-root-causes).

1. **Doctor and guard.** Run `scripts/ai/doctor.sh`, then `scripts/ai/sim.sh guard`. If a plain launch dies, the environment is broken. Fix that first, and nothing measured before now counts (principle-environment-before-code). **Check.** The guard prints `guard ok`.
2. **Reproduce it yourself, on the surface the user saw.** Drive it the way `/verify` does. Use a launch-argument seam (`scripts/ai/sim.sh launch <args>`), a deep link (`scripts/ai/sim.sh openurl <url>`), or an XCUITest for a real gesture. If no seam reaches the state, add a DEBUG-fenced one. It stays, and a line in `.claude/ios-screens.txt` makes it the regression path. If it will not fire directly, synthesize the trigger, tighten the conditions (text size, locale, store size, network), or instrument until it does. Ask the user to reproduce only with a stated reason the harness cannot reach it, after driving it as far as it goes. If a faithful reproduction is impossible, record the exact limitation and never present the nearest path as equivalent evidence. **Check.** A repro with a rate, such as 4/6 launches, and its output saved.
3. **Separate three facts before naming a cause.**
   - The **trigger** is the input, event or transition that starts the fault.
   - The **masking condition** is the independent state, timing, cache, size class, text size, locale or runtime that hides or exposes it. It explains "sometimes" without being the cause.
   - The **symptom** is what the person sees, often several layers downstream.

   **Check.** All three are written down, each with its evidence.
4. **Binary-search the cause.** Form the candidate hypotheses, then rule them out until one survives. Seed them with `/how` over the affected subsystem and `/why` for the regression history. Compare against a proven path (another screen, another text size, the previous commit, the other store) and find the earliest meaningful divergence in inputs, state, timing or control flow. `git bisect` over the seam when a good commit exists. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add `Logger` lines or `os_signpost` intervals and read them as the code runs (`playbooks/runtime-forensics.md` for a hang, a leak or a spin). Read the `.ips` (`scripts/ai/sim.sh crashes <epoch>`) before theorizing, and remember some traps write none (`scripts/ai/sim.sh alive` after the action). Do not guess. The most recent nearby change is not causal without evidence. Drive a long or stubborn hunt with `/loop`. **Check.** One mechanism survives, confirmed by runtime evidence, and every eliminated hypothesis has the observation that killed it.
5. **Name the counterfactual and the disconfirming check.** The counterfactual is the smallest change that should flip the outcome if the surviving mechanism is true. The disconfirming check is the observation that would falsify it. Run both. Keep contradictory results. Do not explain them away. **Check.** Both ran, and their results are recorded verbatim.
6. **Write the failing check first** when it is cheap. A unit test on the pure logic (Swift Testing or XCTest, per `/tdd`), a UI test, or a scripted seam run with a pass condition. Skip it when the test would be expensive, integration-heavy or unclear, and say why. **Check.** It fails, and fails for the reported reason.
7. **Plan the fix at the root.** No nil-guard that silences a crash, no retry that hides a race, no `DispatchQueue.main.asyncAfter` that outruns a timing bug. If the fix crosses a function boundary, run `/architect` first. Delegate the implementation to an `ios-agent` subagent (model from `MODEL_CODE` in `.claude/ios.env`, `sonnet` by default, `opus` for gnarly concurrency) with a specific scope: the files, the mechanism, the failing check, the success criterion. Review the diff yourself. **Check.** Every changed line traces to the confirmed mechanism, and anything a refuted hypothesis motivated is reverted.
8. **Verify on the same surface, the same number of times,** with the guard between runs. 4/6 failing becomes 6/6 passing. "Inconclusive" or a different surface is not a pass. Flag it. Then run `python3 scripts/ai/blast-radius.py <changed files>` and re-capture every surface it names, at the default and the largest accessibility size. A fix to a shared view or token regresses screens you did not open. Run the full suite with `scripts/ai/test.sh`. Unit tests green is not "bug absent". **Check.** The original repro passes at the original rate, and the failing-then-passing output is saved.
9. **Run `/verify`.** It runs the gates, then the AI judge on the visual sheets, recorded by `scripts/ai/history.py judge`. A sheet nobody judged is not verified. **Check.** Every gate passes and the visual verdict is PASS, or each failure is explained.
10. **Commit in order.** The failing check first, then the fix on top, so the history proves itself (principle-sequence-verifiable-units). Stage by path. The message states symptom, trigger, masking condition, fix. **Check.** `git log` shows the check before the fix.
11. **Ask whether the lesson belongs in structure** (principle-encode-lessons-in-structure). `/reflect` puts it there. **Check.** A test, a hook, a type or a line in a playbook now guards the return, or the reply says why none is worth it.
12. **Run the Opening a PR playbook** (`playbooks/opening-a-pr.md`), which opens it with `scripts/ai/pr.sh`. **Check.** The PR link exists.

**Reply:** what the person saw; trigger, masking condition and symptom; the divergence from the proven path; the counterfactual and disconfirming check with their results; the root cause and the fix; repro rate before and after, with the failing-then-passing output pasted verbatim and the evidence paths; what now guards against a return; the PR link.
