# Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.** A long task the owner steps away from ("run until it's done", "I'm going to bed, keep going"). The bar is higher, not lower. Nobody is watching, so every claim must be checkable when they return. A program that outlives one agent is `playbooks/orchestrate.md`.

1. **Write the contract first,** as the first todo items. The goal. The exit condition as a checkable predicate (a test passes, a screenshot shows X at AX5, a crash rate goes from 4/6 to 0/6, an eval reaches N with the gate held, all N PRs merged). What you will not do without the owner (Autonomy, in the `ios-loop` skill). Where the decision log lives (`.build/reports/<date>-<slug>.md`). **Check.** The predicate is something a command or a screenshot can answer yes or no.
2. **Pick the wake mechanism, never a sleep.** An event to watch (a build, CI, a merge, a branch moving) wakes you on the event. Long builds, test runs and evals run with `run_in_background`, whose completion wakes you, so never poll them. A `Monitor` watches a log for the line that matters (`BUILD SUCCEEDED|error:`) instead of re-reading it. Work that waits on something slow with no event uses `/loop` in dynamic mode (and `ScheduleWakeup`, where this build of Claude Code has it), with the delay sized to when the result is worth re-checking and a long heartbeat as fallback. Independent slices go to their own worktrees or cloud sessions (`playbooks/delegate.md`), each with its own simulator and DerivedData, and `/lead` tracks them. **Check.** Exactly one wake mechanism per thing you wait on.
3. **Make the smallest change the evidence justifies, per iteration.** Verify it against the predicate. Commit it if it moved the predicate. Revert it if it did not. A belt-and-braces change that "might help" is reverted, not left to ride. Sequence the work into verifiable units and verify each before the next, exactly as the matching playbook says (principle-sequence-verifiable-units). The Stop hook will not let a turn end on a broken build. Answer it with a fix, not a disclaimer. **Check.** Every commit in the run names the predicate movement it produced.
4. **Mid-run discoveries are yours.** A broken script, a related bug, a flaky test, a stale playbook line, review noise, a tooling failure, fixable drift. Fix them in their own commit and their own PR, then return to the predicate. Do not park reversible work for the owner and do not stop to ask. Surface only irreversible actions, genuine product or preference calls no experiment can settle, and real dead ends. **Check.** Each side fix has its own PR or commit, and the predicate is still the main drive.
5. **Park genuine product decisions, never the run.** Park that branch of work. Log the decision with options and a recommendation. Where a default lets work continue, take the one cheapest to reverse and record the one word that reverses it. Continue with everything that does not depend on it (principle-never-block-on-the-human). **Check.** Every default you chose for the owner has its reverse word in the log.
6. **Log every iteration** as one line in the decision log (or a `/show-me-your-work` trail). Time, what changed, evidence, whether the predicate moved, reversible or not. **Check.** The log has a line for every iteration, including the ones you reverted.
7. **Stop only when the predicate is met.** A plateau is not a stop. Change approach and push past it (principle-attack-the-premise). Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory. **Check.** The predicate's command or screenshot says yes, or the dead end is written up with what was tried.
8. **Close out.** Put each unit's gate results (`python3 scripts/ai/history.py last <sha>`) and evidence paths in the report, and open each unit's PR with `scripts/ai/pr.sh`. **Check.** Every unit has a PR link and a gate result.

**Reply (when the owner returns):** the exit condition and its final state, the iterations run, what landed and what was reverted, the decisions made for them (each with its reverse word), the parked decisions (one at a time, per `principle-never-block-on-the-human`), and the decision log path.
