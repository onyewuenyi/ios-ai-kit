# Feature

**You own the design. Plan, review, verify.** Delegate the implementation. Stay in the lead. Name the data shape before writing logic, and name how you will prove it works before writing views.

1. **Read the neighbourhood.** Run `/how` over the affected subsystem. Read the models, the view that hosts the feature, the design-system tokens, and the project's rules (CLAUDE.md, `.claude/rules/`, docs). Match its idioms in naming, comment density and concurrency style. **Check.** You can name the files the feature touches and the idiom each follows.
2. **Name the data shape** and its organizing structure (principle-model-the-domain). The state the feature owns, who writes it, where it persists, which actor it lives on. Prefer an enum or state machine over parallel booleans, a table or registry over branching, a typed model over a shape assumption repeated across files, and a derived value over a stored one that can drift. If it touches Core Data, SwiftData or CloudKit, the schema part follows `playbooks/schema-change.md` (principle-additive-data). **Check.** The shape is written in the todo list as Swift types.
3. **Explore the design with `/architect`** whenever the code crosses a function boundary. It runs parallel design explorations and returns the alternatives. Pick one and say why. **Check.** A chosen shape, with the rejected alternatives in a table.
4. **Name the proof.** Which seam, deep link or UI test will reach the new state, and what end state proves it. If none exists, the seam is part of the feature (DEBUG-fenced, added to `.claude/ios-screens.txt` with an `expect:` label). **Check.** The launch arguments and the expected label are written down.
5. **Write the throughput checkpoint** as four todo items. A dimension that does not apply keeps its item as `n/a: <reason>` rather than being dropped.
   - **Blocking first steps.** Gates that run before any fan-out (the data shape, a shared token, a migration).
   - **Independent workstreams.** Disjoint files, views or layers parallelize. Shared writes serialize.
   - **Shared mutable state.** Default to splitting the target (principle-separate-before-serializing-shared-state). Serialize only for real invariants.
   - **Smallest safe decomposition.** If one worker is best, name why.

   **Check.** All four items exist.
6. **Delegate the code.** Hand it to an `ios-agent` subagent (model from `MODEL_CODE` in `.claude/ios.env`, `sonnet` by default, `opus` for cross-cutting design or concurrency) with a specific scope: file paths, the named data shape and its structure, the proof from step 4, and the success criteria. When the implementation admits several valid shapes (error handling, an abstraction layer, test structure), delegate through `/arena` instead, so the runners surface the alternatives and the cross-judge guards the pick. Delegation is mandatory. The gain is review separation, not lines saved, so principle-laziness-protocol does not override it. A subagent forbidden to spawn satisfies this by owning the diff with the same review separation. Build the smallest vertical slice a user could see, behind a flag if the rest is not ready. Keep a comment only for a non-obvious why. Port a shared-primitive improvement to every consumer and verify each. **Check.** You reviewed the diff, and `scripts/ai/build.sh` is clean.
7. **Unit-test the pure logic** (ranking, parsing, state transitions) the way callers call it, asserting literal expected values (principle-test-behavior-not-implementation, `/tdd`). **Check.** `scripts/ai/test.sh` is green, and each new test fails when its logic is broken.
8. **Verify on the surface.** Cover every surface `python3 scripts/ai/blast-radius.py <changed files>` names, not just the one you built, at the default size and at the extremes (principle-extremes-are-the-test). That means the largest accessibility text, the smallest device, iPad if shipped, dark and light. Motion gets a frame sheet (`scripts/ai/sim.sh record out.mov 8 & sleep 1; scripts/ai/sim.sh launch <seam>; wait`, then `scripts/ai/sim.sh frames out.mov sheet.png`). VoiceOver gets a spoken equivalent for every gesture, and anything hidden for the eyes is hidden from VoiceOver too. "Inconclusive" or a different surface is not a pass. Flag it. **Check.** A screenshot or frame sheet you looked at for every named surface, at each size.
9. **Check the Release side** if you touched Info.plist, entitlements, permissions, launch arguments or third-party SDKs (principle-release-is-another-app). Run `scripts/ai/verify.sh --release` (the seams gate plus the Release audit). **Check.** The release gate passes, or the step is marked `skip: no Release-relevant change`.
10. **Run `/verify`.** It runs the gates, then the AI judge on the visual sheets, recorded by `scripts/ai/history.py judge`. A sheet nobody judged is not verified. **Check.** Every gate passes and the visual verdict is PASS.
11. **Commit in verifiable units** (principle-sequence-verifiable-units). Build, verify and commit each small unit before the next, then rebase into small ordered commits and stack follow-ups. Stage by path. Update `.claude/ios-screens.txt` (`/map refresh`) and any checklist docs in the same change that changes a flow. **Check.** Each commit builds on its own.
12. **If the design was contested, run `/interrogate`** on the diff before calling it done. **Check.** Every finding is fixed or dismissed with a reason.
13. **Run the Opening a PR playbook** (`playbooks/opening-a-pr.md`, `scripts/ai/pr.sh`). **Check.** The PR link exists.

Code-coupled work (one feature, one migration) goes to a single owner with the checkpoint inline. That owner fans out internally after the blocking phase. Parent-level fan-out is for slices that produce independent artifacts (audits, cross-subsystem investigations, competing experiments). Rewrite the checkpoint at phase boundaries. Spawn a fresh owner with consolidated scope rather than chaining interrupts.

**Reply:** what the person using the app can now do; the data shape you chose and why, with a table when there were real alternatives; the throughput checkpoint; the evidence at each size and device, with paths; the open decisions; the PR link.
