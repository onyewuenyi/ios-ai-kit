# Trace forensics

**You own the diagnosis from the artifact. Load it, shape it, narrow to the cause, attribute to source.**

Distinct from `playbooks/runtime-forensics.md`, which instruments the live process. Here the capture already exists, often from a device or a user you cannot reach. The artifact is a fixed dataset. Read it, do not re-run it. Keep every artifact and every script you write under `.build/forensics/<slug>/`.

1. **Identify the format and load it with the right tool.** Parse large artifacts in a subagent and keep the reduced finding in the main thread (principle-guard-the-context-window).
   - **Instruments `.trace`.** `xcrun xctrace export --input <trace> --toc` lists the runs and tables. `--xpath` exports one table as XML.
   - **Crash report `.ips`.** Two JSON documents, a one-line header and a body. The body names `exception`, `termination`, `faultingThread` and each thread's frames. Simulator crashes come from `scripts/ai/sim.sh crashes <epoch>`. Device crashes come from Xcode's Organizer or `~/Library/Logs/CrashReporter/MobileDevice/<device>/`.
   - **Spindump or hang report.** Text. Read it in an editor or with `grep`.
   - **sysdiagnose.** A `.tar.gz` (from a device, `xcrun devicectl device sysdiagnose --device <id>`). Unpack it. Its `system_logs.logarchive` reads with `log show --archive <path> --predicate 'process == "<executable>"'`. It also holds spindumps, `ps` output and `JetsamEvent-*.ips` memory-pressure kills.
   - **Memory graph `.memgraph`.** `leaks <file>`, `heap <file>`, `vmmap -summary <file>`, `malloc_history <file> <address>` when stack logging was on at capture.
   - **MetricKit payload.** JSON from `MXMetricPayload` or `MXDiagnosticPayload`. Diagnostics carry a `callStackTree` of frames as binary UUID plus offset.

   **Check.** You can name the format, the capture surface (device model and OS build, or simulator), the app build, and the time window.
2. **Transform it into a form you can query.** Load the rows into sqlite, one row per sample, frame, thread or node, with a small script (principle-build-the-lever). Reach the queryable shape before you read. Bracket the parse by reproducing a total the tool itself reports, such as the sample count or the total bytes (principle-explain-the-number). **Check.** Your query's total matches the tool's.
3. **Narrow to the cause.** Query for the frames that hold the most time and walk the call tree to the hot path. For a leak, follow the retainer chain from the leaked object to a root (`leaks --traceTree=<address> <file>`). For a spindump or hang report, find the thread stuck on-CPU or blocked, and its wait reason (the main thread on a lock, a semaphore, synchronous XPC, file I/O). For a crash, read the faulting thread and the exception type first. `EXC_BREAKPOINT` on Swift code is a trap (a force unwrap, an out-of-range index, a `fatalError`). `EXC_BAD_ACCESS` is a bad pointer. A `0x8badf00d` termination is the watchdog killing a blocked main thread. A jetsam event is memory. **Check.** One thread, frame or object is named, with its share of the total.
4. **Attribute to source.** Map the hot frame to file, symbol and line through the artifact's own symbols. Symbolicate a trace with `xcrun xctrace symbolicate --input <trace> --dsym <App.app.dSYM>`. Resolve a raw frame with `atos -arch arm64 -o <App.app.dSYM>/Contents/Resources/DWARF/<App> -l <load address> <address>`. Match the binary UUID in the artifact to the dSYM with `dwarfdump --uuid`. A frame with no source mapping is not yet a diagnosis. **Check.** A file:line, or a plain statement that the artifact carries no symbols and which build's dSYM would resolve them.
5. **Confirm against a paired capture** when you have one. Diff a before and an after artifact, two builds, or a good and a bad device, with the same query. Without one, mark the finding as the strongest hypothesis the artifact supports, not a confirmed cause. **Check.** The finding is labelled confirmed or hypothesis.
6. **Hand back a cited diagnosis.** No fix unless asked. Route to `playbooks/bug-fix.md` or `playbooks/perf.md` once the cause is known. A crash that you can now reproduce becomes Bug fix's failing check. Write the throughput checkpoint as one line, `throughput checkpoint: n/a, read-only forensics`. **Check.** The diagnosis cites the artifact path and the query that produced each number.

**Reply:** the artifact, its format and its capture stamp; the reduced finding with its numbers; the source location; the artifact and script paths; whether a paired capture confirmed it.
